## 1. 问题

当前 `/interaction` 已能返回 `need_clarification + questions[]`，但 UI 仅展示文字列表，用户只能在通用文本框继续输入。系统没有结构化选项、待澄清计划、风险等级或执行前确认协议，难以支撑后续“全部组件 + JS”能力安全放开。

## 2. 已确认产品决策

1. 用户语义明确且属于低风险、本地、可逆操作时，Agent 直接生成候选并进入预览，不做无意义追问。
2. 上传、远程数据源、页面跳转、浏览器存储、`eval`、覆盖既有手写事件等动作属于高风险，必须 Ask-before-act。
3. 生成的事件 JS 继续禁止任何网络请求；远程数据与上传只能通过设计器原生的声明式配置和受管连接执行。
4. 既有手写事件同时支持合并与覆盖：默认尝试安全合并；不能证明安全时必须让用户选择“前置合并 / 后置合并 / 覆盖 / 取消”。

## 3. 功能需求

### FR-1 结构化澄清协议

`questions[]` 升级为带稳定 ID 的结构化问题：

- `single_choice`
- `multiple_choice`
- `text`
- `confirm`

每题可含候选项、推荐项、默认项、是否允许自定义输入和风险说明。答案须以结构化数据返回，不再依赖模型从拼接文本猜测用户选择。

### FR-2 待执行计划

Agent 在需要澄清时返回 `pendingPlan`，至少展示：

- 已确认目标；
- 仍有歧义的组件、位置和交互；
- 计划新增/修改/删除的节点；
- 计划写入的事件；
- 风险等级及原因；
- 回答问题后预计执行的步骤。

澄清期间不得写入画布。

### FR-3 风险等级

- **L0**：只读分析、无写入。
- **L1**：本地可逆属性/结构候选、纯前端确定性 JS；语义明确时直接生成候选，仍须预览后确认写入。
- **L2**：上传、声明式远程数据源、跳转、storage、`eval`、事件覆盖、批量删除或重建；必须结构化确认。
- **L3**：凭据写入、任意网络 JS、生产外部写、不可逆动作；本版本拒绝，除非后续形成独立受权能力。

### FR-4 Ask-before-act UI

AiChat 必须提供：

- 单选/多选选项；
- 自由输入；
- 推荐项说明；
- 风险徽标；
- “继续生成 / 返回修改 / 取消”；
- 刷新前会话内的 pending 状态保持。

### FR-5 多轮闭环

至少覆盖：

`ambiguous → need_clarification → 用户回答 → generated → preview → confirmed → applied`

每轮答案与问题 ID 关联；旧问题不得在新计划中被误复用。

### FR-6 事件冲突决策

检测到既有手写事件时：

1. AST 可安全组合时提供前置/后置合并预览；
2. 无法安全组合时不得静默覆盖；
3. 覆盖必须单独确认并展示旧代码与新代码差异；
4. 用户取消时画布保持不变。

## 4. 非目标

- 本版本不扩大组件创建白名单；
- 不实现任意网络请求 JS；
- 不实现跨刷新、跨设备长期会话；
- 不以澄清 UI 替代真实预览验证。

## 5. 验收标准

1. 结构化问题支持单选、多选、文本和确认。
2. 明确的 L1 指令不会被强制追问。
3. 每种 L2 动作均在生成候选前触发确认。
4. 多轮澄清闭环有 API、UI、Playwright 验收。
5. 事件冲突支持合并与覆盖，覆盖无确认必拒绝。
6. 任意生成 JS 中出现网络调用仍被静态和运行时双重拦截。
7. 未回答、取消、答案过期或计划漂移时画布不变。

## 6. 风险

- 过度提问降低效率：以风险和歧义双阈值控制。
- 选项由模型伪造：候选组件、字段和动作必须由 Catalog/当前表单校验。
- 澄清后表单已变化：pending plan 绑定 form fingerprint，漂移后重新规划。
- 合并事件改变执行顺序：预览必须分别验证所选顺序。
